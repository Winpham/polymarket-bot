# FORGE_DEBATES — RUN-TRADER-PROFILES hardening

Record of the 4-agent Forge pass (Opus diagnostician → Direct + Rethink designers → reality-check/assembler) that produced `RUN-TRADER-PROFILES.md`. Verification findings + per-gap synthesis.

## PART 1 — Reality verification (against the real code)

- **F1 — `ON CONFLICT … WHERE <pred> DO NOTHING` / batch-splitting (weak → simplified).** The predicate is required only in the *inference* form (`ON CONFLICT (cols) WHERE pred`). **Bare `ON CONFLICT DO NOTHING` needs no target, honors all (both partial) unique indexes, and dedups intra-batch** — proven by the existing `insert_window_votes` test. So Direct's "split the UNNEST batch by `tx_hash.is_some()`" is unnecessary; use ONE insert with bare DO-NOTHING.
- **F2 — Rethink trader-native blind baseline + `promotion_verdict` reuse (sound).** The surplus-over-blind, event-clustered (`COALESCE(event_slug,condition_id)`), `width_bucket(price,0,1,5)` structure of `consensus_scoreboard_by_strategy` is reproducible on `trader_fills`; a fleet `blind` per band neutralizes favorite-loading; `promotion_verdict` is drop-in with `n = slice count`.
- **F3 — `surplus_bounds` upper-bound helper + private probit (sound).** `probit` is private in `promotion.rs` (binary); a sibling `pub fn surplus_bounds(...) -> (lo, hi)` in the same module calls it without exporting. Math identical to the gate's lower-bound, symmetric for the Avoid test.
- **F4 — Double-neutralizing blind baseline AND shrink-to-0 (weak → corrected).** Both designs shrank the point estimate before the verdict. That double-penalizes N (the one-sided `se = sd/√N` + the ≥30 floor already handle small samples). **Decision:** verdict uses RAW event-clustered surplus + sd; shrink-toward-0 moves to the continuous `earned_quality` weight (P4), where it regularizes a multiplier rather than a hypothesis test.
- **F5 — Frozen `category`/sport vs SQL slug-CASE (resolved).** Freeze the slug-derived `sport` + `is_sports` into a `trader_fills.sport` column at capture — single source of truth, same heuristic as the consensus path, no per-query-site CASE drift. No extra migration (table is new in 026). Gamma `category` deferred (cost-zero, no lazy cache).
- **F6 — Independent unresolved source + cap + multi-outcome winner_index (broken without it).** Housekeeping resolves only `unresolved_consensus_signals` conds ⇒ non-consensus `trader_fills` markets never resolve ⇒ survivorship bias. Fix: `trader_fill_unresolved_conditions(min_age, cap)` UNIONed into the cond set; `winner_index = tokens.position(|t| t.winner)`. **Added correction:** if `closed && winner_index.is_none()` (void/refund) **skip** — don't charge every BUY a loss.
- **F7 — `PollResult` signature + 429 (weak → corrected).** Adopt Direct's `PollResult{trades, raw_count}` (raw page length for the gap test) — **not** Rethink's `got_429` field; a 429 returned as `Ok` would let ingest advance the cursor and lose data. Detect `status==429` before `error_for_status` (which discards status), record a metric, return `Err` (cursor not advanced ⇒ gap re-fetched).
- **F8 — `CONSENSUS_BOOKS_FROM_FILLS` flag cutover (sound).** `books_from_window_votes(&[WindowVote])` is the single shared builder; `load_buy_fills_since` returns the same shape and reuses it. Re-derived `quality` can shift the ranking `score` slightly, but alerts are non-regressive because tiers key on `net_count`. Flag + dual-write + deferred retirement (Rethink).
- **F9 — Cached slow-refresh trust map (sound).** Trust inputs change ~daily; the cycle runs every 1 min. `Arc<RwLock<HashMap>>` + `TRUST_REFRESH_MINS=60` instead of per-cycle recompute.
- **F10 — Non-regression claims (sound, with required edits).** Tiering on `net_count` ⇒ weight/trust can't move a `strict` tier. New `TraderVote` fields default to `(quality, true)` ⇒ `TrustWeighted==Quality`, `trusted_only` drops nothing. Required edits folded into P4: update every `TraderVote` literal + 2 test helpers, the `WeightMode` match, `family()` EXPERIMENTAL list, and extend `default_strict_is_non_regressive`; arms behind `CONSENSUS_TRUST_ARMS` default-false.
- **F11 — pg_dump claim was FALSE in the diagnostic (broken assumption → corrected).** Verified `scripts/consensus-backup.sh` runs `pg_dump -U bot polymarket | gzip`, rotates 14 dumps, launchd-scheduled, documented at `DATA-MODEL.md:44`. So the v1 prompt's "backed by the existing daily pg_dump" was CORRECT; the Forge dossier's "no pg_dump" was wrong. The brief states the truth and still adds `TRADER_FILLS_RETENTION_DAYS`.
- **F12 — leaderboard clamp / widen-via-periods (sound).** `fetch_leaderboard_n` `limit.clamp(1,50)` ⇒ widen via `TRACK_PERIODS`, never N>50.
- **F13 — fills-as-`consensus_signals` rejection (confirmed correct).** `consensus_signals` has `UNIQUE(strategy,condition_id,outcome_index)` + many NOT-NULL aggregate columns ⇒ inserting raw fills would collapse multiple fills and violate NOT-NULLs. Fills get their own table.
- **F14 — Semaphore / 429 metric (sound).** Poll fan-out is an unbounded `join_all` burst today; `Semaphore(8)` + `record_data_api_429` (copy the `record_consensus_*` metric siblings).
